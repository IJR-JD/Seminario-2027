UNIDAD 01 · DECISIÓN DE PLATAFORMA

Por qué Godot y no Blender o Unity como motor principal

TecnologíaQué enseñaCuándo usarlaLímite real
Godot 4Nodos, escenas, GDScript, física, 2D/3D y exportacionesMotor estándar del cursoExportación web exige Compatibility/WebGL 2
BlenderModelado, rigging, texturas, animación 3DCrear personajes, objetos y escenariosNo incluye el antiguo Blender Game Engine
UnityC#, escenas 2D/3D y física profesionalRuta optativa de profundizaciónSoftware propietario con condiciones de licencia
Phaser + JavaScriptDOM/Canvas, game loop, lógica 2D y despliegue webJuegos web de baja demandaNo ofrece 3D como motor integrado

Godot tiene licencia MIT y es abierto; Blender es un entorno de creación de contenido. Unity Personal puede ser gratuito según elegibilidad pero no es software libre. La decisión se basa en una propuesta educativa única para 2D y 3D, no en un benchmark de los nueve PC.

Decisión institucional propuesta: Godot 4 Standard + GDScript para ambos entornos; Blender para recursos 3D; Phaser/HTML5 como respaldo si la prueba de WebGL 2 falla en algún PC.
UNIDAD 02 · AMBIENTE DE TRABAJO

Del equipo apagado al primer proyecto

  1. Descargar: entra en godotengine.org/download y elige Godot Standard 4, no Godot .NET. Los archivos oficiales incluyen instrucciones para cada sistema operativo.
  2. Abrir el editor: ejecuta Godot y selecciona New Project. Crea una carpeta sin espacios problemáticos, por ejemplo guardianes_2d.
  3. Renderer: selecciona Compatibility desde la creación del proyecto si se prevé publicación HTML5.
  4. Escena: en el panel Scene añade un nodo raíz Node2D (para el juego 2D) o Node3D (para el 3D). Guarda como main.tscn.
  5. Script: selecciona el nodo raíz, pulsa Attach Script y crea main.gd. Elige GDScript.
  6. Proyecto: en Project → Project Settings → Application → Run configura la escena principal.
  7. Ejecutar: F6 prueba la escena actual y F5 el proyecto. Abre Debugger cuando aparezca un error.

Importa uno de los dos ejemplos listos para editar

Descarga la carpeta del proyecto desde GitHub (o clona el repositorio completo). En Godot pulsa Import y selecciona project.godot. Se cargarán main.tscn y el script main.gd.

git clone https://github.com/IJR-JD/Seminario-2027.git
# En Godot > Import > selecciona:
# Seminario-2027/projects/godot-examples/guardianes-2d/project.godot

Para el 3D importa la carpeta guardianes-3d. Estos archivos son código fuente real; sus pruebas en el editor y en el laboratorio quedan pendientes.

UNIDAD 03 · CONCEPTOS DE PROGRAMACIÓN

Comprende cada línea antes de copiar código

Variables y tipos

var vidas: int = 3
var velocidad: float = 220.0
var nombre: String = "Luma"
var jugando: bool = true

var crea una variable. int guarda enteros, float decimales, String texto y bool verdadero/falso. Cambia vidas y observa cómo debería responder el juego.

Condiciones

if vidas == 0:
    print("Game Over")
elif vidas == 1:
    print("Última oportunidad")
else:
    print("Continúa")

if toma decisiones. == compara valores; = asigna. La indentación delimita cada bloque. Diseña una condición para abrir una puerta solo cuando tengas tres objetos.

Funciones

func sumar_puntos(valor: int) -> void:
    puntaje += valor
    print(puntaje)

Una función agrupa pasos reutilizables; recibe parámetros. -> void indica que no retorna un valor. Antes de usar el ejemplo debes declarar var puntaje := 0.

Bucles y colecciones

var objetos := [2, 5, 9]
for objeto in objetos:
    print(objeto)

Una lista (Array) almacena varios elementos; for recorre cada uno. En el videojuego, una colección contiene las posiciones de los núcleos de energía.

Actividad 1: escribe cinco variables del juego, dos decisiones, una función para sumar puntos y un bucle que recorra tres objetos. Explica cada línea y predice la salida antes de ejecutarla.
UNIDAD 04 · ARQUITECTURA GODOT

De un nodo a una escena reutilizable

En Godot, un nodo tiene una responsabilidad (dibujar, recibir entradas, mover un cuerpo o mostrar texto). Una escena guarda una jerarquía de nodos; puede instanciarse muchas veces. El script añade comportamiento.

Main (Node2D) — escenario 2D
├── Player (CharacterBody2D) — movimiento del jugador
│   ├── Sprite2D — imagen
│   └── CollisionShape2D — forma física
├── Bot9 (CharacterBody2D) — enemigo
├── Collectibles (Node2D) — objetos
└── HUD (CanvasLayer) — información fija en pantalla

Esta es la arquitectura de destino después del primer prototipo. Los archivos fuente proporcionados construyen formas directamente con código para eliminar dependencias y ayudar a comprender primero los fundamentos. La siguiente tarea consiste en separar Player y Bot9 en escenas independientes.

UNIDAD 05 · VECTORES Y TIEMPO

Cómo programar movimiento 2D

extends Node2D
var posicion := Vector2(100, 100)
const VELOCIDAD := 220.0

func _process(delta: float) -> void:
    var direccion := Input.get_vector(
        "ui_left", "ui_right", "ui_up", "ui_down"
    )
    posicion += direccion * VELOCIDAD * delta
    queue_redraw()

func _draw() -> void:
    draw_circle(posicion, 20, Color.GREEN)

extends Node2D indica qué tipo de nodo controla el script. Vector2(x, y) representa posición y dirección en dos dimensiones. Input.get_vector lee las flechas y devuelve un vector normalizado. delta indica segundos entre fotogramas, de modo que VELOCIDAD * delta representa distancia recorrida en ese intervalo. queue_redraw vuelve a dibujar.

Experimento de velocidad

Prueba velocidades de 100, 220 y 400 unidades/s y recorre la pantalla durante dos segundos. Calcula la distancia teórica d = v × t y compara con la observada. Explica por qué no debemos sumar una cantidad fija por fotograma.

UNIDAD 06 · CONTACTO Y FÍSICA

¿Cómo sabe el juego que el jugador tocó un objeto?

var jugador := Vector2(120, 90)
var objeto := Vector2(140, 110)
var radio_jugador := 18.0
var radio_objeto := 12.0

if jugador.distance_to(objeto) < radio_jugador + radio_objeto:
    print("¡Núcleo recogido!")

Esta aproximación compara centros y radios: funciona bien para objetos circulares, pero no resuelve toda la física de un escenario. Para paredes y plataformas se recomienda utilizar CharacterBody2D, CollisionShape2D y move_and_slide().

# Script para un nodo CharacterBody2D (con CollisionShape2D)
extends CharacterBody2D
const SPEED := 220.0

func _physics_process(_delta: float) -> void:
    velocity = Input.get_vector(
        "ui_left", "ui_right", "ui_up", "ui_down"
    ) * SPEED
    move_and_slide()

_physics_process se ejecuta en pasos físicos, velocity indica velocidad en unidades/s y move_and_slide() resuelve el deslizamiento contra superficies físicas. Debes crear un collider para el jugador y los obstáculos; sin CollisionShape2D no habrá bloqueos reales.

UNIDAD 07 · PROGRAMAR INTELIGENCIA ARTIFICIAL

Una IA sencilla que decide qué hacer

Para empezar, la IA de enemigos no necesita un modelo de lenguaje. Es suficiente definir percepción → decisión → acción. En el ejemplo, Bot-9 detecta la distancia al protagonista y pasa de patrulla a persecución.

var modo := "PATROL"
var robot := Vector2(700, 220)
var jugador := Vector2(100, 90)

func actualizar_ia(delta: float) -> void:
    var distancia := robot.distance_to(jugador)
    if distancia < 190:
        modo = "CHASE"
    elif distancia > 270:
        modo = "PATROL"

    if modo == "CHASE":
        robot = robot.move_toward(jugador, 90.0 * delta)

La separación entre los umbrales (190 y 270) se denomina histéresis y evita cambios excesivos de estado. move_toward limita cuánto avanza el robot cada vez.

IA de nivel 1: FSM

Estados PATROL, CHASE y SEARCH. Cada estado define un objetivo y transiciones. Introduce una variable last_seen_position para recordar dónde se observó por última vez al jugador.

IA de nivel 2: navegación

Si el mapa contiene paredes, seguir una línea recta no basta. Para 2D utiliza una cuadrícula con BFS o AStarGrid2D; para 3D, una malla de navegación y NavigationAgent3D.

El videojuego HTML5 anterior implementa una IA más avanzada con FSM y BFS; los proyectos Godot comienzan con la FSM para facilitar que un estudiante sin experiencia comprenda la decisión antes de añadir algoritmos de rutas.

UNIDAD 08 · TRANSICIÓN A 3D

¿Qué cambia al agregar una tercera dimensión?

La lógica de objetivos, variables, funciones y estados sigue siendo prácticamente igual. Cambian el espacio, la representación visual y los sistemas de cámara y colisión.

En 2DEn 3DInterpretación
Vector2(x,y)Vector3(x,y,z)Se añade la profundidad
Node2DNode3DÁrbol de nodos con transformación espacial
Sprite2DMeshInstance3DDe imagen a malla
CharacterBody2DCharacterBody3DColisiones y movimiento físico
Camera2DCamera3DProyección del mundo a la pantalla
AStarGrid2DNavigationAgent3DRutas en escenarios con obstáculos
extends Node3D
const SPEED := 5.0

func _process(delta: float) -> void:
    var direction := Vector3.ZERO
    if Input.is_key_pressed(KEY_W): direction.z -= 1
    if Input.is_key_pressed(KEY_S): direction.z += 1
    if Input.is_key_pressed(KEY_A): direction.x -= 1
    if Input.is_key_pressed(KEY_D): direction.x += 1
    position += direction.normalized() * SPEED * delta

Y es la altura y X/Z forman el plano del suelo en el ejemplo. El código mueve un Node3D sin físicas; para colisiones reales cambia a CharacterBody3D y configura un CollisionShape3D. Añade una Camera3D con current = true y una DirectionalLight3D para visualizar geometrías.

UNIDAD 09 · MODELADO DE PERSONAJES

Blender → Godot: del modelo a un objeto jugable

  1. Modelo base: crea un personaje low-poly con cubos, esferas y extrusiones. Define una silueta reconocible para estudiantes pequeños.
  2. Topología: mantén pocos polígonos y controla normales. Evita geometrías ocultas y modificadores innecesarios.
  3. Materiales: usa una paleta pequeña, contraste alto y colores consistentes; no dependas solo del color para diferenciar personajes.
  4. Rigging (ampliación): crea un armature si necesitas animaciones de brazos, piernas o cabeza; para el primer proyecto no es obligatorio.
  5. Exportar: aplica transformaciones cuando corresponda y utiliza File → Export → glTF 2.0 con formato .glb.
  6. Importar: copia el .glb a la carpeta Godot, deja que el editor lo importe y arrastra la escena importada al escenario.
  7. Juego: crea un collider separado de la malla visual y ajusta escala, origen, dirección y animaciones.

Una malla bonita no constituye por sí misma un personaje jugable: debe conectarse a scripts, entradas, cámara y colisiones. Blender es herramienta de creación; Godot administra la interacción en tiempo real.

UNIDAD 10 · EXPORTACIÓN Y PUBLICACIÓN

De Godot a un juego para el laboratorio

Opción A — Ejecutable local: exporta para Windows o el sistema real del laboratorio, copia el paquete y prueba políticas de ejecución. Su funcionamiento no depende del navegador, pero puede requerir autorización para ejecutar archivos.

Opción B — HTML5: en Godot ve a Project → Export → Add → Web, instala las export templates correspondientes y utiliza Compatibility. Exporta, publica los archivos generados juntos en un servidor HTTPS y verifica WebGL 2 en cada navegador.

Para Godot 4, evita C# si la entrega debe ejecutarse desde el navegador. El proyecto puede exportarse sin hilos para simplificar requisitos de alojamiento, según las opciones de la versión de Godot utilizada.

Distinción crítica: GitHub Pages aloja el HTML5 exportado, pero no convierte automáticamente el código GDScript del repositorio en un juego web. El exportado web incluye HTML, JavaScript y recursos que deben publicarse como un conjunto.

Como plan B, la página actual ya dispone de un juego HTML5 en JavaScript/Canvas que no requiere exportación desde Godot: Guardianes del Laboratorio web.
