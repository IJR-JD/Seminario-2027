01 · CONFIGURAR EL ENTORNO

Instala las herramientas correctas

Ruta A — Sin instalaciones (primer día)

Abre el ejemplo directamente desde la página del colegio. Está escrito con HTML5 Canvas y JavaScript sin bibliotecas externas. Ideal para entender la estructura antes de aprender motores.

  1. Abre el videojuego.
  2. Prueba con WASD, Enter y P.
  3. Abre herramientas de desarrollador con F12 y observa Console.
  4. Consulta el código del juego desde el repositorio en GitHub.

Ruta B — Phaser y un proyecto profesional

Instala Node.js LTS, Visual Studio Code y Git. Utiliza la plantilla oficial de Phaser y selecciona Web Bundler → Vite.

node --version
npm --version
git --version
npm create @phaserjs/game@latest mi-juego
cd mi-juego
npm install
npm run dev

Abre la dirección local que muestra Vite. Los comandos dependen de la plantilla elegida y del entorno; comprueba package.json si alguna orden cambia.

¿Qué carpeta y archivos debería tener?

mi-juego/
├─ index.html
├─ package.json
├─ public/
│  ├─ sprites/          # Personajes y animaciones
│  ├─ audio/            # Efectos originales/licenciados
│  └─ maps/             # Niveles JSON
├─ src/
│  ├─ main.js           # Inicialización del juego
│  ├─ scenes/           # Menu, Gameplay, GameOver
│  ├─ entities/         # Player, Enemy, Collectible
│  ├─ systems/          # Input, Collision, AI
│  └─ data/             # Configuración de niveles
└─ README.md

En el prototipo suministrado concentramos todo en un único index.html para que sea fácil inspeccionarlo. Para proyectos más grandes se deben separar módulos y responsabilidades.

Referencias oficiales: Phaser Installation y Create Phaser Game.

02 · CHARACTER DESIGN

Del concepto al personaje jugable

Luma · protagonista

Silueta: circular. Paleta: verde y blanco. Rol: recoger núcleos y resolver el nivel. Se dibuja en código: no requiere imagen descargada.

Bot-9 · enemigo inteligente

Silueta: rectangular. Paleta: rojo y blanco. Rol: patrullar, perseguir y buscar a Luma. Sus tres estados se muestran en pantalla para facilitar la depuración.

  1. Brief: identifica la edad de los jugadores y escribe tres atributos del personaje.
  2. Concept art: crea tres variaciones de forma, paleta y expresión antes de elegir una.
  3. Sprite: dibuja con Canvas, SVG o una herramienta de pixel art; usa recursos propios o licenciados.
  4. Animaciones: define idle, movimiento, recolección y derrota. Un sprite sheet puede organizar 4–8 fotogramas por acción.
  5. Accesibilidad: diferencia aliados y enemigos también por forma, no únicamente por color.
IA para ideación y recursos (opcional):

Puede ayudar a proponer siluetas, escribir una ficha de personaje, depurar errores o preparar una lista de pruebas. No sustituye el diseño, el código ni la verificación de los alumnos. Evita introducir datos personales de menores en herramientas externas; declara los recursos generados y revisa sus licencias.

03 · SOFTWARE ENGINEERING

Organiza la lógica del juego

Un juego no es solo dibujar un personaje. Se repite un ciclo de entrada → simulación → renderizado y se gestiona un conjunto de estados para el menú, la partida, la pausa y el resultado.

const states = ['ready', 'playing', 'paused', 'won', 'lost'];
function frame(now) {
  const dt = Math.min((now - previous) / 1000, 0.05);
  previous = now;
  if (state === 'playing') {
    updatePlayer(dt);
    updateEnemyAI(dt);
    checkObjectives();
  }
  drawScene();
  requestAnimationFrame(frame);
}

Delta time evita que la velocidad dependa de cuántos cuadros dibuja el PC. Limitar dt también reduce saltos anormales tras cambiar de pestaña. En la demo, Enter inicia, P/espacio pausa y perder el foco pausa automáticamente.

04 · MOVIMIENTO, COLISIONES Y EVENTOS

Haz que el personaje responda correctamente

const length = Math.hypot(inputX, inputY) || 1;
player.x += (inputX / length) * player.speed * dt;
player.y += (inputY / length) * player.speed * dt;

Normalizar el vector impide que moverse en diagonal sea más rápido. La demo separa el desplazamiento horizontal del vertical y comprueba círculos contra rectángulos para impedir cruzar las paredes. El contacto con núcleos registra una sola recolección.

Pruebas imprescindibles

  • Caminar en las cuatro direcciones y en diagonal.
  • Intentar atravesar muros y bordes del mapa.
  • Recolectar un objeto sin duplicar el puntaje.
  • Pausar y reanudar sin modificar el temporizador.
  • Reiniciar después de ganar o perder sin variables residuales.

05 · ARTIFICIAL INTELLIGENCE FOR GAMES

Construye una IA verificable, no una ilusión

La IA del enemigo Bot-9 es una máquina de estados finitos (FSM) con búsqueda de rutas BFS. No utiliza un modelo generativo ni servicios en la nube: es inteligencia artificial basada en reglas y búsqueda en grafos.

Estados del enemigo

  1. PATROL: sigue puntos de control.
  2. CHASE: detecta a Luma si está a menos de 170 píxeles y persigue su última posición conocida.
  3. SEARCH: explora esa posición cuando pierde el contacto.
  4. RETURN: vuelve a patrullar si termina su búsqueda (implementado como transición a PATROL).

Búsqueda de caminos

  1. Divide el escenario en celdas de 30 píxeles.
  2. Descarta las celdas bloqueadas por paredes.
  3. Desde la celda inicial, explora vecinas accesibles con BFS.
  4. Reconstruye el camino al destino.
  5. Recalcula la ruta aproximadamente cada 0,28 segundos.
// Idea central de BFS: explorar vecinos libres
const queue = [startCell];
const previous = new Map([[startCell, null]]);
while (queue.length) {
  const current = queue.shift();
  if (current === goalCell) break;
  for (const next of accessibleNeighbors(current)) {
    if (!previous.has(next)) {
      previous.set(next, current);
      queue.push(next);
    }
  }
}
// Luego reconstruir la ruta desde goalCell.

En la demo real se utiliza una cola con índice de lectura para evitar shift() repetidos. BFS encuentra rutas mínimas en número de movimientos sobre una cuadrícula no ponderada. No crea una estrategia humana ni garantiza comportamiento óptimo en todos los mapas. Un nivel más avanzado puede incorporar A*, línea de visión, árboles de comportamiento y dificultad adaptativa.

Experimento de IA:

Abre la demo, atrae a Bot-9 y escóndete detrás de un muro. Observa el estado mostrado en la pantalla y registra si el robot encuentra un camino, si pierde al jugador y cómo retoma su patrulla. Cambia el radio de detección y contrasta resultados.

06 · LEVEL DESIGN & USER EXPERIENCE

Diseña niveles para grados inferiores

Comienza con un nivel que enseñe movimiento sin riesgo. Después introduce la mecánica de recolección y finalmente el enemigo. El primer minuto debe explicar visualmente el objetivo sin lectura extensa.

NivelObjetivoNuevo conceptoCriterio de prueba
TutorialLlegar a una puertaMovimiento y paredesEl jugador aprende sin ayuda
ExploraciónRecoger 3 núcleosObjetos y puntajeNo hay recolectas duplicadas
GuardianesRecoger y escaparPatrulla, persecución y riesgoReto comprensible y reinicio fácil

La demo entregada implementa el nivel Guardianes. Los niveles Tutorial y Exploración son actividades de ampliación propuestas, no niveles ya disponibles.

08 · VERSION CONTROL & DEPLOYMENT

Publica un juego reproducible

git init
git add .
git commit -m "feat: prototipo jugable del laboratorio"
git branch -M main
# Crea el repositorio en GitHub antes de añadir remoto
git remote add origin https://github.com/USUARIO/mi-juego.git
git push -u origin main

Para una página estática, GitHub Pages puede servir el proyecto con un index.html y recursos relativos. Si el proyecto usa Vite, configura la ruta base para el nombre del repositorio y publica los archivos generados por npm run build, no los fuentes sin compilar. Si se desarrolla con Godot, exporta para Web con el renderizador Compatibility y valida el navegador y los recursos reales.

Referencia: Godot · Exportar para la Web.

09 · USER TESTING

Deja que los jugadores reales decidan qué mejorar

  1. Asigna un código de juego y una versión verificable; entrega las instrucciones impresas o en pantalla.
  2. Organiza nueve estaciones independientes, con partidas de 5 a 10 minutos.
  3. Invita a estudiantes de grados inferiores a jugar sin asistencia constante.
  4. Observa dónde dudan, en qué pantalla abandonan y qué errores aparecen.
  5. Desde Game Lab, evalúa diversión, controles, diseño visual, dificultad y experiencia general.
  6. Exporta las calificaciones anónimas a CSV antes de cerrar la pestaña.
  7. Prioriza tres mejoras y repite una segunda sesión con una nueva versión.
Privacidad y persistencia:

El formulario actual no tiene backend: sus evaluaciones permanecen solo en la memoria de la pestaña y deben exportarse. No solicites nombres, correos ni fotografías de estudiantes menores de edad. El almacenamiento central exige una implementación posterior con controles de acceso.
