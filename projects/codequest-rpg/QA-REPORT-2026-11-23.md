## 1. Code and gameplay inventory

| Subsystem | Code | Reviewed behavior |
|---|---|---|
| Core adventure | `world.js`, `index.html`, `world.css` | UI state, game scenes, browser storage, character editor, room renderer, execution and scoring |
| Intro levels | `world.js` | Twelve fixed 9×9 educational grid rooms and directional assignments |
| Traversal | `expedition.mjs` | Four rooms with walk/jump/dash/fly, elevation, crystals and relay constraints |
| Logic | `logic.mjs` | Six rooms (Signal Grove, Clockwork Bastion, Ember Foundry), nested conditionals, sensors, locks, sentries and hazards |
| Open island | `overworld.mjs` | Six regions, 22 portal buildings, camera orbit/survey, WASD, sprint, jump, crouch, two ladder towers, three NPCs and eight saved relic discoveries |
| Optimization | `room-stars.mjs` | Three-star thresholds based on executed steps, best score saved per room |
| Skills | `skills.js`, `skill-motion.js` | Separate 3D skill preview lab with class-specific animations |
| **New: Python Trail** | `island-exploration.mjs`, island/atlas integration | Five waystations, local progress, navigation cues and bridge-safe path planning |

The lesson language is a **restricted interpreter**, not CPython: `compile` recognizes only four direction assignments and context-specific abilities; `compileLogic` recognizes sensor-based `if`/`else`; `evaluate` parses numeric arithmetic and known movement variables. It does not execute arbitrary Python syntax, imports, loops, functions or file I/O. The new Python Trail provides concept previews **only**, not executable examples in the movement editor.

## 3. New expansion and acceptance criteria

- **Five optional monuments** geographically dispersed on valid dry terrain: Variable Spring, Operator Stones, Branching Woods, Iteration Cape, Data Observatory.
- Each monument displays a 3D marker; physically approaching saves progress under `cq-island-python-trail-v1`. Previously completed station examples appear in the Explorer's Atlas.
- The atlas shows clue, coordinates, discovery state, active waypoint and distance/bearing. It does **not** teleport players or publish student records.
- A touch-only directional pad supports press-and-hold traversal and releases movement on pointer cancellation or loss.
- Click-to-walk is routed via one of three existing bridges when needed, including bank-to-bank, bridge-to-bank and bridge-to-bridge paths.
- Original 22 rooms, 8 collectible relics, room stars, editor commands and stored room progress remain unchanged.

## 4. Verification and release gate

**Static and logic QA:** `scripts/qa-codequest.mjs` (12 beginner rooms, 4 expedition rooms, logic puzzles, hazards, star thresholds); `scripts/qa-codequest-skills.mjs` (all 11 skill tracks); `scripts/qa-codequest-island.mjs` (5 safe stations, geometric bounds, segment-by-segment routing, DOM/UI wiring, D-pad release hooks).

**Browser QA:** `scripts/qa-codequest-browser.mjs` exercises WebGL initialization, island dialog, 5 atlas entries, waypoint cues, camera map mode, all 22 doors, persistence after reload and touch D-pad press/release. It captures desktop and mobile screenshots in `qa-codequest/`. CI serves local branch files and locally pinned Three.js modules to avoid external CDN variability.

**Before merging:** Require green PR CI (both Node and Chromium), inspect screenshots for legibility/overlaps, manually visit multiple districts and new monuments, confirm no room regression, and validate on a low-end school laptop and phone. Passing Node tests alone does **not** prove visual fidelity, GPU performance or actual in-game collection behavior.

**Deployment:** GitHub Pages is built from `main`; this PR remains isolated until explicitly merged. No production release claimed.
